### 日志配置属性和意义

| **属性**  | **描述**                                                     |
| --------- | ------------------------------------------------------------ |
| prefix    | 以符号;作为分隔符。表示该模块所表示的包的前缀。由prefix所指出的包都属于该模块的日志输出 |
| inherited | false表示从他开始不能继承父模块的日志输出,true表示可以       |
| pattern   | 该模块输出的日志格式，详细察看格式描述章节内容               |
| level     | 该模块的日志输出控制级别，默认为继承父模块的调试级别         |
| file      | 该模块的日志输出文件                                         |
| time      | 表示该日志按照时间进行滚动，他为一个日期格式的字符串，必须是java.text.DateFormat能够解释的字符串，日志按照日期格式的最小精度进行滚动，如.yyyy.mm.dd  表示按天滚动。该属性只有在file属性已设置才起作用 |
| size.maxSize  | 表示日志按照日志文件大小进行滚动，他打单位可以为KB或者MB，如10KB,表示日志文件在10KB左右发生滚动行为 |
| size.maxIndex | 数值类型，表示该模块的最大日志数，该模块的所有日志文件不会超过这个数值 |

> ldebug: 非常详细的信息输出，一般是在产品运行环境进行调试性输出
>
> linfo:对产品发生的一些特殊事件进行输出，如服务启动、停止
>
> lwarn: 警告，一般在产品运行在非期待的分支上时进行输出，这种非期待的分支一般对业务没有实质影响
>
> lerror: 产品运行错误，非常重要







### 异常的分类  

所有的异常类都继承BusinessExceptoin和BusinessRuntimeException

- JVM错误：这种类型的错误由 JVM 抛出。
  - OutOfMemoryError 就是 JVM 异常的一个常见示例。对 JVM 异常您无能为力。它们表明一种致命的情况。唯一得体的退出办法是停止应用程序服务器（可能要增加硬件资源），然后重新启动系统。
- 非JVM错误(Error)：表示对整个系统的处理具有严重影响的错误，
  - 如cache溢出，中间件框架启动失败等等。这类异常一般需要中间件方面的参数调整或者重新启动系统。
- 受查异常：受查异常是一种定制异常，由应用程序或第三方的库抛出，它们预示了处理逻辑中的某个条件尚未满足。          
- 非受查异常：在大多数情况下非受查异常由 JVM 作为 RuntimeException 的子类抛出。
  - 例如，NullPointerException 或 ArrayOutOfBoundsException 将因代码中的错误而被抛出。另一种类型的非受查异常在系统碰到配置不当的资源时发生，在这种情况下，系统不能进行合适处理，因此作为非受查异常抛出颇有意义。还有的规则是，如果您对某个异常无能为力，那么它应当重新封装为非受查异常抛出。





### 组件开发

*（图片缺失：image-20231116201310596.png）*

#### 模块

- 组件部署和管理的容器
- 对应：NC_HOME/modules目录，目录下有moudle.xml文件

- moudle.xml可以提供模块的一些公共特性的定制，如classloader的策略
- 模块从设计上应尽量的减少对其他模块的依赖耦合
- 模块之间可以通过优先级控制启动顺序

#### 组件

- 框架进行部署、运行和管理的最基本单元
- 组件在表现形式上为.upm文件中的一个由component元素标识的描述信息
- 组件开发推荐使用基于接口的开发模式
- 组件之间的关系可以通过依赖注射进行解决
- 组件从名称空间的隔离上看，分为公共组件和私有组件

##### 共有组件

- 模块通过公共组件对外部模块提供服务（Facade模式）
- 公共组件体现为在upm文件中配置在public区域中的组件
- 公共组件和JNDI使用相同的名称空间
- 公共组件可通过框架提供的名称服务进行查找
- 公共组件一般是一些静态的服务，服务没有生命周期的控制

##### 私有组件

- 用于模块内部使用的组件，一般为细粒度的业务实现
- 不建议使用名称服务进行对该组件的引用，建议使用依赖注射
- 一些具有运行时服务的组件一般配置为私有组件
- 私有组件的名称空间限于模块内部，不同模块之间具有不同的私有名称控件
- 私有组件的名称空间不能与公又组件的名称空间冲突
- 私有组件体现为在upm文件中配置在private区域中的组件

单例和原型

- 实现nc.bs.framework.component.Singleton的组件为单例组件

远程组件

- 模块通过远程组件，暴露服务给远程的外部客户端
- 远程组件必须是公开的，要么生存于ESA容器中，要么生存于JNDI中
- 远程组件必须具有接口
- NC中远程组件必须是无状态单例组件

活跃组件

- 活跃组件在容器初始化时生成组件实例；是单例的
- 继承自nc.bs.framework.component.AciveComponent的组件自动为活跃组件
- 活跃组件潜在用途
  - 组件初始化效率低，为了不影响系统的运行效率
  - 对容器的扩展需要，要求组件的生存与容器的生存同时生效
  - 希望通过优先级控制一组组件的初始化顺序(?)

服务组件

- 服务组件是具有明晰的启动和停止逻辑的组件，单例的、无接口的、私有的、
- 服务组件的启动和停止是不允许阻塞式
- 服务组件可以通过实现nc.bs.framework.component.ServiceComponent或者按照JSR252进行开
  发

`AnteSearchClusterListener4NC`同时是 服务组件和活跃组件

组件可以指定集群性质，通过servicerun.xml在实施时绑定其集群特性

模块和组件都具有优先级



### 依赖注射

- 依赖注射是实现反转控制的基本手段
- 容器提供了构造注射和属性注射功能
- 容器在注射过程中自动进行类型转换，并支持泛型
- 基于属性的依赖注射可以循环依赖，但是循环依赖应该从设计上尽量避免
- 依赖注射的组件名称控件包括：JNDI,所有的公共组件，本模块中的私有组件
- 后台服务之间的关系尽量的采用依赖注射进行解决，而不是名称服务
- 对私有组件的依赖只能通过依赖注射进行解决

在upm文件中进行依赖注射

- 构造注射：construct/parameter
- 属性注射：property
- 值元素
  - value: 指出一个常量值，系统会把改值转化为适合的数据类型
  - bean: 一个嵌入的java对象
  - ref: 对其他组件的引用，引用的对象可以为任何数据类型
  - list: 用于设置列表或者数组类型，它是个集合类型，可以包含所有的值元素
  - map: 一个map类型，如哈希表，它是个集合类型，可以包含所有的其他的值元素
  - set: 没有重复元素的集合类型，可以包含所有其他的值元素
  - props: 表示java.util.Properties,由名称/值构成，值为string类型

### 对象缓存

文档：对象缓存6.5技术红皮书

缓存介于应用程序和物理数据源之间，其作用是为了降低应用程序对物理数据源访问的频率，从而提高应用的运行性能。缓存有两个问题需要重点考虑，一个是内存占用，一个是数据的有效性。NC6.1缓存模型分为两级，内存级缓存以及文件缓存。内存级缓存又可根据内存占用控制方式的不同有多种缓存策略。同时，缓存提供了两个“版本敏感”的Map包装类：[VersionSensitiveMap](http://techserver/pm/VersionSensitiveMap)和[ElementVersionSensitiveMap](http://techserver/pm/ElementVersionSensitiveMap)，以解决数据的有效性问题。

NC6.3缓存在6.1两级缓存的基础上，新增加了大数据缓存（堆外缓存）。大数据缓存同样位于内存中，是由ByteBuffer.allocateDirect分配的直接内存空间。存储容量大，速度相对较快且不受JVM GC的影响。但存储的数据必须是可序列化的数据。
