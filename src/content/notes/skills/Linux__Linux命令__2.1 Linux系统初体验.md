##### 目录结构

**阶层式的树状目录机构**

Linux的文件系统采用阶层式的树状目录机构，在该结构中的最上层是根目录“/” ，然后在根目录下再建立其它的目录。

Linux中无论操作系统管理几个磁盘分区，这样的目录树只有一个。从结构上讲，各个磁盘分区上的树型目录不一定是并列的。

**目录结构**

![未命名](https://jcstrong.github.io/img/20210207033424.jpg)

###### /bin

可执行、普通用户可使用

###### /boot

引导加载程序相关的文件，——映像文件也常放在这里

###### /etc

各种系统配置文件。用户账户密码文件、系统初始化文件、安装的应用软件和服务的配置文件

###### /usr

庞大。应用程序和文件都在这个目录

/usr/bin

目录下集中了大多数用户命令，是系统的软件库

/usr/include包含了C语言的头文件，用来描述C语言程序中用到的数据结构、函数和常量。

/usr/lib包含了程序库文件，系统不变的数据文件。编译程序时，程序回会和其中的库进行连接。另外有许多程序把配置文件存入其中

/usr/sbin包括了跟系统不必要的系统管理命令，例如多数服务程序

###### /var

用于经常变化的文件，如数据库等，包含系统运行时要改变的数据。这些数据所在的目录的大小是要经常变化和扩充的

###### /sbin

是系统管理员使用的管理程序、超级用户的二进制文件

###### /temp

存放临时文件，系统重启不会被保存

###### /dev

存放设备文件，设备驱动程序。用户通过这些文件访问外部设备

###### /home

个人工作目录，存放个人配置文件，如个人环境变量等。所有账号分配一个工作目录

###### /root

是超级管理员的文件夹，当root用户登录时，root目录就是工作目录

###### /lib

是根文件系统上的程序所需的共享库，包含了可被许多程序共享的代码，可使可执行文件变得更小

###### /mnt

系统管理员临时挂载文件系统的挂载点，如挂载的U盘

##### 文件类型

Linux系统中任何设备都是以文件形式存在的

可以使用``ls -lh 文件名``来查看文件类型，输出的第一个字符代表这个文件的文件类型

###### 普通文件-

通常是流式文件。可直接阅读的文件，可分为纯文本、二进制、数据文件

 `# ls -lh install.log`

`-rw-r--r-- 1 root root 53K 03-16 08:54 install.log`

###### 目录文件d

用于表示和管理系统中的全部文件

```\# ls -lh```

``drwxr-xr-x 2 root root 4.0K 04-19 10:53 mydir``

###### 链接文件l

用于不同目录下文件的共享

```\# ls -lh setup.log```

``lrwxrwxrwx 1 root root 11 04-19 11:18 setup.log -> install.log``

###### 设备文件c

包括块设备文件和字符设备文件

  `# ls -la /dev/tty`

`crw-rw-rw- 1 root tty 5, 0 04-19 08:29 /dev/tty`

###### 管道(FIFO)文件p

 提供进程间通信的一种方式 

###### 套接字(socket) 文件s

该文件类型与网络通信有关

`ls -lh /var/lib/mysql/mysql.sock`

`srwxrwxrwx 1 mysql mysql 0 04-19 11:12 /var/lib/mysql/mysql.sock`

##### 分区

Linux默 认可分为3个分区，分别是boot分区、swap分区和根分区

可以用`fdisk -l`命令查看分区情况

##### 挂载(Mount)

Linux下的分区需要挂载到目录后才能使用，挂载的意义就是把磁盘分区的内容放在某个目录下。

把分区和目录对应的过程 叫做**挂载(Mount)**而这个挂载在文件树中的位置就是**挂载点**。

当要使用某个设备时，例如要读取硬盘中的一个格式化好的分区、 光盘或软件等设备时，必须先把这些设备对应到某个目录上，而这个**目录**就称为“**挂载点(mount point)**”，这样才可以读取这些设备， 将物理分区细节屏蔽掉，用户只有统一的逻辑概念， 所有的东西都是文件。

Complex Instruction Set Computer, CISC
指令数目多、复杂、长度不相同，执行时间长
#### 常见的CISC指令集CPU
AMD、Intel、VIA等x86家架构CPU
>因为最早都是由8086架构上发展出来，故称x86架构。2003年以前Intel开发的x86从8位、16位升级到32位，后来AMD开发出64位，后来的64位pc统称为x86_64架构
#### 32位和64位
CPU 每次能够处理的数据量称为字组大小（ word size ），字组大小依据 CPU 的设计而有 32 位与 64 位。我们现在所称的计算机是 32 位或 64 位主要是依据 CPU 解析的字组大小而来的！早期的 32 位 CPU 中，因为 CPU 每次能够解析的数据量有限，因此由内存传来的数据量就有所限制了。这也导致 32 位的 CPU 最多只能支持最大到 4GB 的内存。
